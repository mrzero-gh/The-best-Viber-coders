# Генератор эпизодов (роль A)

Строит вымышленную компанию за один месяц со скрытыми ошибками. Формат файлов — `docs/contract.md`, разделы 3, 4, 9, 11–15.

## Запуск

```powershell
# один эпизод (конфиг необязателен: без него — встроенный по умолчанию)
python -m generator.build --seed 42 --out episodes/train --config schemas/examples/config.train.json
# печатает: EP-XXXXXXXX <sha256 эпизода>

# история ошибок и отвлекающих случаев — только для оценщика, читает private/
python -m generator.explain episodes/train/EP-XXXXXXXX
python -m generator.explain episodes/train/EP-XXXXXXXX ISS-XXXXXXXX
```

Из кода: `generator.build.generate_episode(seed, config, out_dir, id_seed=None) -> Path`. Его вызывает `env.server`.

## Модули

| Файл | Что делает |
|---|---|
| `config.py` | значения по умолчанию и проверка конфига (без jsonschema) |
| `rng.py` | потоки RNG `content` / `ids` / `errors` / `distractors`, ID base32 Крокфорда |
| `history.py` | чистая история: курсы, контрагенты, счета, платежи, проводки |
| `distractors.py` | 4 отвлекающих случая |
| `errors.py` | 4 типа ошибок и 2 совмещённых сценария |
| `build.py` | сборка и запись `public/` и `private/`, CLI |
| `explain.py` | причинная история каждой ошибки по `provenance.json` |

## Порядок построения

1. План: число ошибок, сценариев и отвлекающих случаев (под них резервируются строки книги и документы).
2. Чистая история: все документы в периоде, по каждому документу дебет = кредит.
3. Отвлекающие случаи (законные): разбитый платёж, возврат, повторяющийся счёт прошлого месяца, документ в 23:xx последнего дня.
4. Ошибки: сначала совмещённые сценарии, потом одиночные. Документы одной ошибки не трогает другая ошибка или отвлекающий случай.

## Гарантии (проверяются тестами `tests/test_generator_*.py`)

- Тот же `(seed, config, generator_version)` → те же sha256 открытых файлов (`private/generation.json`).
- `id_seed` меняет только ID, суммы и даты остаются прежними (для парных проверок со сменой ID).
- Каждая ошибка доказуема по открытым записям: `grader.certificate` подтверждает 100 % ошибок и отвлекающих случаев на 60 случайных конфигах; oracle получает F1 = 1.
- 200–2000 проводок, 20–200 документов, ≤ 12 ошибок, время ISO-8601 со смещением манифеста, деньги в целых minor units, курсы — десятичные строки, без float.
- Формула проводок платежа совпадает с `grader/evidence.payment_book`.

## Решения, которые стоит знать

- Прошлый счёт «повторяющейся услуги» и его проводки лежат в прошлом месяце, до периода: сертификат требует разные месяцы. Он всегда в базовой валюте, потому что курсов месяц назад в `fx.csv` нет.
- Ошибка периода: документ датирован за границей периода (до 7 дней), а проведён внутри, в последние 1–3 или первые 0–2 дня периода.
- Ошибка FX: курс другой даты (±1–5 дней) или искажённый на 1–5 %; расхождение ≥ 100 minor, чтобы не путаться с допуском.
- Ошибка распределения не вносится, если 1 minor валюты платежа дешевле 1 minor базовой (например, KZT при базе USD): тогда разнесённую сумму нельзя однозначно восстановить.
- Если кандидатов не хватило, генератор вносит, сколько получилось. Запрошенное и внесённое видно в `generation.json` (`errors_planned` / `errors_injected` и т. д.).
- У компании только в базовой валюте ошибок FX и сценариев с валютой нет.
