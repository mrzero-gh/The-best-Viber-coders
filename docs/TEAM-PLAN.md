**Must (без этого нет баллов):**
1. Генератор: 4 типа ошибок, 2 совмещённых сценария, чистые компании, ≥3 отвлекающих случая, инварианты под тестами.

**Should — наши «вау» (из IDEAS.md):** `make jury`, галерея взломов, канарейки, сертификат разрешимости, график «сложность → F1», отпечаток эпизода, `explain`, местный контекст (KZT, +05:00).

**Could (только если всё готово до заморозки):** просмотрщик траекторий в терминале, экспериментальная награда рядом с общей.

**Won't:** веб-интерфейс, обучение весов, LLM-агент, платные API, новые типы ошибок сверх четырёх.

## 5. Работа в Git

Подробно — в `CONTRIBUTING.md`. Главное:
- В `main` напрямую не коммитим. Ветка `имя/задача` → Pull Request → сливает капитан B.
- Каждый работает в своих папках (таблица ролей). Контракт, схемы и `requirements.txt` меняет только B.
- PR каждые 2–4 часа, перед PR: **Branch → Update from main** и `pytest`.
- CI в GitHub Actions запускает `pytest` на каждый PR. Красный CI — не сливаем.
- Владелец `mrzero-gh`: добавить всех в Collaborators и включить защиту `main` (Require a pull request).
